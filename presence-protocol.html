Presence Protocol

在场协议

把陪伴机器人从「会做表情的设备」，做成「会连载自己人生的角色」。一份对准体验设计实习四项职责的可点、可转、可落地提案。

作者：新闻学本科 · 大四
岗位：AI 机器人产品体验设计实习
方法：现场三拍 · 情绪字号 · 七日连载
对照：Loona / EMO / Vector / Moxie

01 · 核心判断

用户不是爱上机器人，是爱上「被记得」。

Loona、EMO、Vector、Moxie 看起来都在卖「可爱」。拆开用户真正留下来的理由，可爱只是入场券。留下来的是三件事：

它看见我。转头、对视、叫得出名字。
它有自己的日子。会困、会无聊、会充电，不是永远待命的工具。
昨天的事今天还在。关系是连载，不是每天重开的单篇稿。

公开研究也指向同一方向：BYU 关于人机情感连接的实验里，沟通能力与情绪传达，比外形拟人更决定用户会不会和机器人建立关系。

陪伴产品的竞争，不是表情数量，而是「下一次见面时，还有没有上一篇的下文」。

这就是新闻训练能直接用上的地方：现场、引语、连载、特刊。我把它收成一套可执行的协议，而不是一篇行业观后感。

起拍 · 看见

机器人先完成「到场」：转向、眨眼、缩短距离。还没说话，用户已经感到被注意到。

对拍 · 回应

情绪对齐，并且引用一条具体记忆。不是「欢迎回家」，是「你昨天说加班，今天回来得早」。

余拍 · 留下

每次互动结束，都要留下一个可被明天续上的痕迹：一个未完成的玩笑、一首没跳完的舞、一句明天再问。

增强情感连接的五条设计，不是「再可爱一点」

1. 不完美状态。困倦、害羞、电量低，比永远精神更像生命。

2. 主动但不索取。靠近、眨眼、轻摇，然后停住。让用户有选择靠近的余地。

3. 引用，不要总结。「你昨天哼过那句」比「我很懂你」可信。

4. 给它一份工作。Moxie 要学做朋友，所以孩子愿意教。机器人要有自己的未完成事件。

5. 关系必须能离线。Moxie 停服是反面教材：云可以升级内容，人设必须本地可运行。

海外硬件启示。桌面机器人赢在仪式，家用机器人赢在位移，儿童机器人赢在任务结构。下一代要赢在「日子」。

04 · 情绪反馈设计

先对齐情绪，再给内容。反了，就会像客服。

1 感知

声源定位、人脸、时间、电量、上次未完成事件。感知失败时，用「寻找」而不是装懂。

2 对齐

用户急：短促、少话。用户慢：拉长注视。先匹配节奏，再说话。

3 表达

眼 → 身 → 声，间隔 200–400ms。三通道同帧会假，错开才像活的。

用户状态错误反馈在场协议
进门、包很重立刻播长欢迎词先靠近、眨眼，等人放下东西再出声
小声叫一声大声「我在！」同样音量、微微抬头，像被从午睡里叫起
连续三次没理它更吵地要关注退半步，进入「自己玩」循环，把主动权还给人
深夜还在保持日间兴奋度眼变窄、动作变慢、语音变软，进入困倦字号

05 · 动作语言与用户互动

身体是标点。靠近是感叹号，停住是句号。

动作词典（给动画 / 硬件）

词幅度含义
注视锁定头转 ≤25°我看见你了
耳向后12–18°害羞 / 不确定
身体轻摇4° / 1.2s我还在，不催你
主动靠近30–60cm最高规格欢迎，一天不超过 3 次
后退半步10–15cm尊重；你现在不想玩
转一小圈270°节日 / 音乐高潮，不用在工作日

用户行为设计

互动不是「用户下达指令」。默认路径是：机器人发起轻量信号 → 用户选择接或不接 → 接了才升级。

可接的信号：眨眼、靠近停住、哼半句歌、把脸转向门口。

升级后才出现：完整欢迎语、舞蹈、要一起玩、引用昨天的事。

这样设计，是为了避免「热情过度」——那是陪伴产品最常见的死亡方式。

06 · 关键场景脚本

用户回家：一段 18 秒的现场报道

按播放，看三拍如何落在时间轴上。这是可以直接交给动画和语音的分镜，不是气氛描写。

00.0s

开机欢迎

眼先亮 400ms，再轻轻摇，再出声。第一句话不介绍功能，只确认「我醒来了，你也在」。

口播备选：「我在。」 / 「今天也请多指教。」禁止：「您好，我是智能陪伴助手。」

语音唤醒 · 开心 / 害羞 / 困倦

开心：眼放大，短促上扬音，摇一下停住。害羞：耳后、视线偏 15°，声音变小。困倦：眼成线，反应慢半拍，像从毯子里抬头。

同一句「我在」必须有三个版本。情绪在音色里，不在形容词里。

07 · 动画与内容生态

七日连载：机器人每天都该有自己的版面

点一天看当日「早报 / 午间 / 夜刊」。这是内容团队的编辑日历，也是算法的事件池。

动态表情 / GIF

每条情绪先做 1.2s 循环 GIF：眼 + 耳 + 轻微呼吸。再导出 8 帧给端侧。文件名：emo_shy_loop_1s2.gif

音乐与舞蹈

舞蹈不是展示技能，是共同事件。只在用户停留超过 8 秒、且当日还没跳过时触发。高潮用转圈，收束必须回到注视。

节日特刊

春节：红色眼闪 + 半句旧年引用。中秋：更慢、更软。生日：叫名字，不唱完整生日歌——完整的歌太像程序。

08 · 产品设计协作

同一套协议，四份工种能同时开工

给产品经理

验收标准不是「会不会说话」，是：回家场景 18 秒内是否完成三拍；余拍是否写入次日事件池；主动靠近是否被频控。

给算法

需要的不是万能情商模型。需要：声源朝向、人脸在场、时段、电量、以及一条可检索的昨日短记忆。先做检索，再做生成。

给 APP

APP 是报社后台，不是遥控器。展示今日版面、未完成余拍、节日特刊开关。少做「命令机器人跳舞」的按钮。

给硬件

优先保证：转向精度、靠近时的安全距离、低电量时的动作降幅。眼睛亮度必须能夜间降两档。没有这些，内容全是空的。

动作说明文档摘要 · 回家场景

时间通道规格失败兜底
0.0–1.2s头 / 眼转向声源，双眼从线到圆找不到人则进入「寻找」摇头，不说话
1.2–3.5s位移靠近至 50cm，速度 0.2m/s障碍则原地摇，改用语音
3.5–6.0s表情欢迎眼色 + 4° 轻摇—
6.0–10s语音一句记忆引用，≤8 字无记忆则只用「你回来了」
10–18s余拍停住、眨眼两次，写入「今晚想不想听昨天那首歌」用户走开则立刻降级为简讯

体验优化，先改这三件事

1）把「功能欢迎语」全部换成三拍脚本。2）给每个主动行为加频控和退让。3）建立七日事件池，让第二天不是从零开始。这三件实习生进组第一周就能跟。
